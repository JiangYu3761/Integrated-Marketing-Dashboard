# Integrated Marketing Dashboard · 产品经营地图

市场部使用的空白前端模板，覆盖营销、平台运营、采购库存、物流、售后、合规和利润协同。

源码仓库：[JiangYu3761/Integrated-Marketing-Dashboard](https://github.com/JiangYu3761/Integrated-Marketing-Dashboard)。这是持续修改和保存版本的主项目。

## 随时修改

- 修改程序：在 Codex 中打开这个仓库文件夹，或在 GitHub 打开对应文件后点击编辑。交互逻辑在 `src/app.js`，外观在 `src/app.css`，页面结构在 `index.html`。
- 修改任务：运行网页后，在日期格添加任务，点击任务弹窗编辑，勾选方框完成。录入的数据保存在当前浏览器，不会随源码提交到 GitHub。
- 修改代码后刷新网页查看。检查通过后提交并推送到本仓库，保留每次修改历史。

本地首次使用：

```bash
git clone https://github.com/JiangYu3761/Integrated-Marketing-Dashboard.git
cd Integrated-Marketing-Dashboard
```

## 运行

### Mac Dock 独立应用

在 Mac 上双击仓库里的 **`安装到Dock.command`**。安装器会将当前项目编译为 **产品经营地图.app**，安装到 `~/Applications`，添加到 Dock 并打开。以后点击 Dock 图标即可使用独立应用窗口，无需手动启动服务或打开浏览器。

- 需要 **macOS 14 Sonoma 或更新版本、Python 3.9+、Apple 命令行开发工具**。首次安装若提示缺少开发工具，在终端运行 `xcode-select --install`，安装完成后再次双击。安装器不会自行下载开发工具。
- 应用使用系统 WebKit，不需要 Chrome、Electron 或前端依赖。附带项目专属图标、编辑菜单和窗口菜单，支持 `⌘R` 刷新、`⌘Q` 退出。
- 关闭窗口后应用继续运行，点击 Dock 图标可再次显示；`⌘Q` 退出应用时自动关闭本地服务。应用异常退出时，附带服务也会自行退出。不会关闭其他程序或强行释放被占用的端口。
- 本地服务只监听 `127.0.0.1:18876`。端口被其他程序占用时应用会提示错误，不会打开其他项目的网页。
- 应用里的数据保存在独立的 WebKit 本地存储中，**不会自动继承 Safari、Chrome 等浏览器内已有的任务**，也不和它们同步。更新应用保持相同安装位置和应用标识，不主动清除本地数据。
- 应用包含安装时的页面副本，并支持在底部“应用更新”区域自动或手动下载安装正式新版。更新 `.app` 不会删除应用之外的本地任务数据。未发布的源码修改仍需重新运行安装器才能更新到本机应用。
- 自动添加 Dock 图标时只追加本应用，保留其他图标；如果系统拒绝修改 Dock，将 Finder 中的 `~/Applications/产品经营地图.app` 手动拖入 Dock 即可。

也可在仓库根目录执行 `bash 安装到Dock.command`。只想生成应用而不安装或修改 Dock，可运行 `python3 scripts/install_macos_app.py --build-only`，输出在 `outputs/macos/产品经营地图.app`。应用在本机编译并使用本地临时签名；不是已公证的通用发行安装包，编译产物对应当前 Mac 的处理器架构。

### 自动与手动更新

首次使用更新功能，需要重新运行安装器，装上带“应用更新”区域的这一版。之后：

- “自动检查并安装更新”默认开启，启动后以及每 6 小时检查一次。也可以点击“检查更新”，手动发现新版后同样自动安装。
- 区域展示当前版本、新版版本、上次检查时间以及检查、下载、待安装或错误状态。浏览器模式会明确提示需要使用独立 Mac 应用，不会声称网页能够替换本机程序。
- 任务弹窗、日格快速输入或设置编辑尚未关闭时，下载后先等待；保存或取消编辑后自动安装并重启。安装过程仅替换应用程序，保留相同应用标识、端口和 WebKit 本地存储。
- 更新只来自本仓库正式的 GitHub Releases，按 Apple Silicon 或 Intel 架构匹配，保持 HTTPS/TLS 验证，并检查包大小、SHA-256、应用标识、架构和 macOS 代码签名完整性。当前使用本地临时签名，发布者身份的信任来自固定的 GitHub 仓库 HTTPS 来源，不是 Apple Developer ID 公证。
- 下载或校验失败不会替换应用；新版启动检查失败会尝试恢复并重新打开旧版。失败的同一版本不会反复自动安装，可手动检查重试。若文件系统故障导致回滚也失败，旧应用备份保留在安装目录旁的 `.dashboard-update-*/previous.app`。
- 更新源必须能公开读取，当前不在客户端保存 GitHub 私有仓库凭据。更新入口不存在时显示“暂未找到可用的已发布更新”，离线时仍可使用当前应用。

发布流程见 [docs/app-updates.md](docs/app-updates.md)。普通源码提交不会成为正式应用更新。当前云环境未执行 Mac 原生升级，更新入口尚未提供可下载的清单；需要先发布正式版本，再在 Mac 上验证从旧版到新版的完整过程。

### 浏览器开发模式

无需安装前端依赖。Mac 可双击仓库里的 `启动.command`。也可进入本目录启动静态服务：

```bash
python3 -m http.server 8876 --bind 127.0.0.1
```

打开 `http://127.0.0.1:8876/`。需要 Python 3。保持服务终端打开；停止时按 `Ctrl+C`。请保持相同端口和浏览器，以读取之前保存的任务。若端口已被占用，先关闭之前启动的服务。

## 已实现

- 项目管理表、人员管理表；一个项目可有多个产品，同一岗位可有多人。
- 每个产品独立时间地图。横轴按月展示，缩放逐步展开到周和天。
- 岗位展开到人员；放大到日视图后，每个日期格内逐条展示任务清单。左侧方框勾选后整条划掉，自动记录实际完成时间；取消勾选清除本次完成时间。
- 双击日格空白处新建任务，自动带入当天日期和对应人员；也可点击格内“＋ 添加任务”，或聚焦日格后按回车。点击任务文字编辑。
- 新建和编辑弹窗默认展示名称、负责人、开始时间、预计完成时间、实际完成时间和备注；岗位、状态、板块、阶段、渠道、验收及每日子任务折叠在详情中。时间按北京时间显示，实际完成时间可手动修改。
- 日格每行一个任务，月视图展示进度，周视图保留任务时间条；跨日任务在对应日期展示，完成状态关联同一任务。有每日子任务时仅展示最细任务，不重复计入父任务。
- 窄窗口自动省略过长标题；放大时间地图后，按可用宽度显示负责人、时间和备注摘要。
- 点击日期或使用日期选择器，查看当天任务清单。
- 勾选任务后整行划线，自动记录实际完成时刻；可取消，也可手动修改时间。
- 按最细任务统计完成数，父任务和每日子任务不重复计算。
- 12 个整合营销板块、6 个经营协同板块，支持阶段、岗位、渠道、市场和状态筛选。
- 阶段排期允许跨月、并行；任务支持前置关系和验收信息。

## 保存与边界

- 初始没有真实人员、任务、业务日期或账户配置。
- 未设置起始月份时，地图临时显示当前月份，不写入虚构的项目排期。
- 数据保存在当前浏览器的 `localStorage`，没有服务器数据库。不同浏览器、设备或端口之间不会自动同步，清理站点数据会删除本地记录。
- 项目文件本身不包含用户在浏览器中录入的数据，Git 提交也不会自动包含这些记录。
- OpenProject、飞书和外部 API 尚未连接，后续方案见 [docs/integration-plan.md](docs/integration-plan.md)。
- 触控板缩放处理已实现并做过事件模拟验证，Mac 实体触控板的操作手感仍需实机验收。

## 检查

有 Node.js 18 或更新版本时运行：

```bash
node scripts/check.mjs
```

Dock 应用的服务、打包资源、安装保护和更新事务检查（Python 3.9+）：

```bash
python3 -m unittest discover -s tests -p 'test_*.py' -v
```

日视图交互回归脚本为 `tests/day-view.cjs`，需要开发环境提供 Playwright 和 Chromium。先启动静态服务，再运行：

```bash
DASHBOARD_TEST_URL=http://127.0.0.1:8876/ node tests/day-view.cjs
```

可通过 `CHROMIUM_PATH` 指定 Chromium 路径（默认 `/usr/bin/chromium`）。脚本在独立浏览器上下文中验证八条任务排列、双击新增、完成时间、人工改时、刷新恢复、跨日状态、人员子任务、滚动和窄屏弹窗，完成后清除该上下文的测试数据。

更新区域的界面与原生消息接口回归：`DASHBOARD_TEST_URL=http://127.0.0.1:8876/ node tests/updates.cjs`。该脚本模拟原生接口验证按钮、状态、编辑保护和窄屏展示，不把模拟结果当成真实 Mac 安装成功。

`.github/workflows/macos-app.yml` 已配置浏览器交互检查，以及 Apple Silicon、Intel 两个平台的测试、编译和更新包校验。Mac CI 还会实际启动原生 AppKit/WebKit 应用，验证任务编辑、完成时间、日格双击和退出后重开恢复。原生测试使用独立的持久化 WebKit 测试配置，不清理用户数据；可在 Mac 构建后运行 `python3 tests/macos_smoke.py`。实际 Dock 操作和完整版本升级仍需验收。

交互验证覆盖日格输入、弹窗编辑、任务勾选和取消、手动完成时间、日期校验、窄窗口及缩放显示、刷新恢复。检查脚本覆盖语法、静态资源引用和超过 16 KiB 的状态保存。模板不是生产环境的多人协作服务。
